# RMSF and Flexible-Segment Profiling

## Goal

This module turns MDCoreAlign from a pure alignment benchmark into a
flexibility-profiling workflow.

The biological question is:

> In conformational ensembles, which residues belong to a stable structural
> core and which residues remain flexible after robust soft-core alignment?

This is more useful for MD users than reporting RMSD alone because RMSF is a
standard residue-level mobility measure.

## Definitions

For an aligned trajectory `x_i(t)`, per-residue RMSF is:

```text
RMSF_i = sqrt(mean_t ||x_i(t) - mean_t x_i(t)||^2)
```

The current implementation reports two RMSF profiles:

- `ordinary_aligned_RMSF`: optional RMSF after ordinary Kabsch alignment to
  frame 0; request it with `--ordinary-rmsf`.
- `robust_aligned_RMSF`: RMSF after continuous-weight alignment to frame 0.

RMSF is alignment-frame dependent. Ordinary and robust RMSF should therefore be
interpreted as two alignment-conditioned flexibility profiles, not as two
absolute alignment-free physical observables.

The output also reports:

- `soft_stability_weight`: average soft core-membership weight across frames.
- `mobility_score`: model-derived soft mobility score, defined by default as
  `1 - soft_stability_weight`; higher means less stable-core-like and more mobile.
- `flexible_segment_id`: contiguous high-mobility segment ID; `0` means not selected.
- `rank`: rank by mobility score, with `1` as most mobile.
- `percentile`: mobility percentile, where larger means more mobile.

## Output Columns

The main CSV table contains:

```text
residue_id
resname
chain
robust_aligned_RMSF
ordinary_aligned_RMSF
soft_stability_weight
mobility_score
flexible_segment_id
rank
percentile
```

These columns are designed for downstream plotting, biological annotation, and
publication figures.

## Minimal Python Example

```python
from mdcorealign import (
    Trajectory,
    build_flexibility_profile,
    write_flexibility_profile_csv,
)

trajectory = Trajectory(coords=coords)  # shape: (n_frames, n_atoms, 3)
profile = build_flexibility_profile(
    trajectory,
    residue_labels=residue_labels,
    rule="huber",
    delta=0.2,
    max_iterations=20,
    warm_start=True,
)
write_flexibility_profile_csv(profile, "flexibility_profile.csv")
```

## Minimal CLI Example

For the user-facing CLI:

```bash
mdcorealign flexibility \
  --input examples/toy_md/toy_ca_trajectory.pdb \
  --input-format ca-pdb \
  --output-dir examples/toy_md/output
```

For a NumPy array trajectory:

```bash
mdcorealign flexibility \
  --input coords.npy \
  --input-format array \
  --output-dir mdcorealign_flex_out
```

## Current Assumptions

- Atom or residue correspondence must be identical across frames.
- The first implementation is CA-friendly and array-first.
- Multi-model PDB support is intentionally minimal and reads CA atoms only.
- Flexible segments are contiguous in input order and are optionally separated by chain.
- `mobility_score` is visualization-oriented and should not replace raw RMSF in quantitative analyses.
- Formal benchmark outputs use `mobility_score_mode="soft_weight"` so that
  `mobility_score` is directly tied to the learned soft core-membership weights.

NhaA and YiiP short are split by chain in the RMSF profile figure so that A/B
chains are not visually merged. Flexible-segment shading uses the formal
`flexible_segment_id` values from the profile tables and does not infer residue
identity from array index.
